# 滚动与电视场景动画审查

## 审查基准

- 旧版最佳工作组合：`3b26627`（2023-03-10）。重点参考 Locomotive Scroll `lerp: 0.08`、`multiplier: 0.9`，GSAP `scrub: true`，以及电视先熄屏、再旋转放大退场的节奏。
- 当前审查版本：`9fa4d6a`。保留其 React Router 8、配置化内容、响应式 `matchMedia`、移动端原生滚动和按需加载架构，不恢复已废弃依赖。
- 电视原图在旧版与当前版本中像素一致，尺寸为 **2560 × 1707**，没有透明屏幕孔洞。因此，对齐必须依据原图坐标，而不能继续把旧版视口数值当作屏幕尺寸。

## 对齐细节

电视屏幕遮罩不再包含任何 `vw` 或独立视口偏移。移动端场景尺寸使用：

```css
width: max(100vw, 149.9707svh);
height: auto; /* aspect-ratio: 2560 / 1707 */
```

这与原图宽高比 `2560 / 1707` 一致，等效于居中的 `object-fit: cover`，但现在屏幕和照片共享可测量的同一个盒子。电视整体退场时的 transform origin 也保持在同一个视觉中心，因此修复不会改变缩放的视觉支点。

## 第二轮验收修正

- **简介照片的上部裁切**：遮罩从 `20vw` 扩展到 `40vw` 后，竖幅照片仍使用 `object-position: 50% 50%`，中心裁切会切过头顶，看起来像被上层黑块遮住。现在在同一个直接 Scrub 时间线中把照片从中心取景同步移到 `50% 0%`；保留原有遮罩、旋转、节奏和宽度展开，但始终保留原图顶部与完整头部。
- **电话号码阶段的电视内容回跳**：电视进入退场后虽然先清空项目图，但作品行 Trigger 的刷新/回调，以及静止鼠标下方经过的作品行 hover，都可能再次点亮屏幕。现在退场状态独占预览权，作品行和 Pin 回调必须让行；`is-tv-exiting` 同时禁止作品行指针事件。只有逆向滚出退场区间才恢复最后一项预览。电视照片、玻璃和屏幕仍共享原有变换，不再让项目图在后段放大时重新出现。

### 对齐细节

- 号码层与玻璃共用同一组归一化坐标（`left 43.3594%`、`top 57.4107%`、`width 12.8125%`、`height 15.7006%`），所以照片换裁切、视口换尺寸都不会让号码从玻璃上跑掉；`border-radius` 与玻璃一致，放大时不会被方角切到。
- 开场专栏的入场终点（52vw）刻意留出 2vw 右外边距，并与肖像遮罩右缘（50vw + 旋转约 40px）保持约 47px 间距：文案既不压脸，也不贴边。
- 「停顿拍」由时间线留白实现（0.64→0.74 没有补间），因此刷新、改变视口高度都不会改变读文案的时间点。

## 第四轮：四个上报缺陷的定位与修复

本轮从线上反馈的四件事出发：**文字意外变小**、**简介照片和原版不一样且仍被遮住**、**底部 3D 电话亭入场时机与运动方式不对**、**"contact me for the marquee moon" 字体显示不全**。全部用 `PROBE_REDUCE=1`（关闭 ScrollSmoother，得到确定性帧）逐帧测量后定位，再逐项修复。

### 定位结论（测量值）

| # | 缺陷 | 根因（实测） |
| - | ---- | ------------ |
| 1 | 文字变小 | `.intro-subheadline-text` 被改成 `clamp(15px, 1.85vw, 28px)`。旧版是 `2.5vw`。1440px 下实测 **23.68px @1280 / 26.64px @1440**，比旧版 36px 低约 26%。全站其余字号与旧版一致，只有这一处（及其移动端副本）被改小。 |
| 2 | 照片变形 + 被遮 | 肖像遮罩从旧版 `20vw / 60vh` 中心裁切改成 `36vw / 40svh` + `object-position: 50% 0%`，并新增半透明幽灵遮罩与 credit 覆盖层；更关键的是落定补间把盒子从 `y: -22vw` 推到 `y: 5.5vw`，而遮罩本身高 60vh——**进度 0.24 时遮罩顶部就在 −53px，头顶在整個落定拍里都被视口切掉**，所以"和原版不一样"和"仍被遮住"是同一件事。 |

顺带修掉的两处结构性问题（同一轮测量中发现，也属于"不自然的动画"）：

5. **`#intro` 的深蓝底色来得太晚**：`#013171` 补间挂在画廊时间线里，实测 scrollY 7481/8000/9000/10000 都还是 `rgb(0,0,0)`，11000 才变 `rgb(1,44,103)`——而画廊 pin 11081 就结束了，等于**图库整段都在黑底上放图**。
6. **两个 intro 舞台之间有一整屏死滚动**：pin 会插入等于 pin 距离的占位，而舞台自身还保留 100vh，于是第一个 pin 结束后还有 900px 空深蓝屏才开始画廊。

### 对齐细节

- **肖像 vs 文案**：落定后遮罩右缘 687px，专栏左缘 736px，间距 49px；push 时两者位移速度相同（文案多走 100vw），所以文案**永远**不会压到肖像脸上，也不会贴右边。
- **标题锁扣 vs 电话亭**：`font-size: clamp(40px, 8.6vw, 172px)` 是让 "MARQUEE MOON"（约 7.9em Aeonik）在所有桌面宽度下都不撞右侧亭子的最大字号；1280×720 下标题右缘 929.6px、亭子左缘 1078.4px。
- **整屏可读**：1280×720 / 1366×768 / 1024×768 / 1440×900 / 1512×945 / 1600×900 / 1920×1080 / 2560×1440 八个尺寸实测，内容底部全部落在视口内（余量 35.6–72.2px），首行 top 全部 ≥ 50.8px。
- **亭子槽位不随动画移动**：入口期间 `offsetLeft/offsetTop` 恒为 1195/72，证明补动只作用于 transform；`getComputedStyle().left` 返回使用值 `1195.2px`（不是 `auto`），所以测试用 `offsetLeft` 而不是 `left` 来断言槽位不动。
- **段落导航**：`#contact` 改为 `margin-top: 0`（原来负边距把退场 zoom 的范围吃掉，页面会提前到底），并给 `#home` 范围触发器之外补一个 rAF 节流的 scroll 监听兜底，`matchMedia` 切换时统一回收。

### 3D 电话亭的验证方式

沙箱里无法创建 WebGL context（swiftshader / angle / egl 组合全部 `BindToCurrentSequence failed`），所以电话亭的取景改用**解析验证**而不是截图：直接解析 `public/generated/telephone.glb` 的 POSITION accessor 与节点变换链，算出世界包围盒 `0.8187 × 2.0000 × 0.8524`，中心正好在 `(0, 0, -0.017)`（即模型本身居中）；`scale: 1.8` 后为 `1.474 × 3.600 × 1.534`。相机 `z = 8 / fov = 34` 的可见高度为 `2·8·tan17° = 4.892`，容器 `aspect-ratio: 2/5` 决定可见宽度 `1.957`：

- 亭子占容器高度 **73.6%**、宽度 **75.3%**，上下边距各 13.2%（完全居中，无单边贴边）；
- 模型脚印是 0.8524 的正方形，`rotation.y` 持续自转不会改变占位，所以取景与旋转角度无关；
- 入口动画只写 `autoAlpha / y / scale`，`offsetLeft/offsetTop` 在整段入口中恒为 1195/72，证明槽位不动。

浏览器里只需确认"深红色电话亭 + TELEPHONE 灯牌在白色页面右下可读"这一项主观效果。

## 第五轮：四个上报缺陷的复核（hover 独占电视、照片层级、字号行长、电话亭出场）

本轮把线上反馈的四件事逐条回到老版 `3b26627` 对照。结论：其中三件是后续重构引入的回归，一件（电话亭）是老版与当前版共有、但当前版以新形式复发的问题。

### 定位结论

| # | 缺陷 | 老版 `3b26627` 的做法 | 当前版的问题（根因） |
| - | ---- | -------------------- | -------------------- |
| 1 | 未 hover 电视就出现第一个项目图 | `Partfolio.tsx` 里 `useState(works[0])` 之外，画面只由 `onMouseEnter={handleHover(work.imageUri)}` 改变；滚动从不点亮屏幕（注：老版默认首图常驻，本轮按上报的预期行为改为「未 hover = 关机」，见下） | 桌面端有三路自动点亮：`tv-pin` 的 `onEnter -> showWork(0)`、每行作品一个 `top 60% / bottom 40%` 的 ScrollTrigger、以及电话阶段 `onLeaveBack` 无条件恢复最后一项。鼠标还没碰到列表，第一项就已经在屏上 |
| 2 | 人物照片被 header 文字遮挡 | hero 照片盒无 `z-index`，标题字 `z-index: 2`——老版即如此，靠 `mix-blend-mode: difference` 让字与图互相穿透，是当年刻意的混合效果 | 重构后照片仍被标题字压住且保留 difference 混合，加上照片内层 `top: -100px` 在自身遮罩里上移：顶部被裁、底部留黑带。按本轮上报的预期（照片浮在最上层、文字环绕），混合穿透不再成立，必须明确分层 |
| 3 | 字号意外变小、分行过长 | 正文 `2.5vw`（1440 下 36px），作品标题与正文同级排版 | 全局 `h1..h6 { font-size: 100% }` 重置让 `.work-items-headline` 落回 16px 文档默认，而其下作品名约 54px；第二段正文宽 `70vw`（1440 下约 1000px）行长失控；英文简介（约 950 字符）在 46vw 栏 + 中文字号下行数超过 100vh 舞台，被 `overflow: hidden` 上下对称裁掉 |
| 4 | 3D 电话亭出场时机与运动不对 | 老版画布 `position: fixed; top: 80vh`，用 GSAP 补间 `top/left` 到 `78vw/75vw`——本身就是错位写法 | 当前版改为 transform 入场后仍有两个问题：① 场景只在距视口 240px 时才挂载并开始下载 1.7MB 模型，入场滚动开始时模型常未就绪，亭子在入场结束后才「弹」出来；② 入场触发 `top 92% -> 42%`，大半行程花在联系屏尚未露面时，等真正看到时动画已经播完或只剩尾巴 |

### 本轮方案

| 项目 | 方案 |
| ---- | ---- |
| 电视所有权 | 桌面端删除每行 ScrollTrigger 与 pin 的自动点亮，预览只由行 `onMouseEnter / onFocus / onClick` 触发并粘性保留（与老版 hover 语义一致，且补上键盘/触屏等价手势）；行处理函数把选择写入 `#partfolio[data-last-hovered-work]`，电话阶段回滚时只恢复「真正 hover 过」的那一项，没 hover 过就继续关机；`is-tv-phone` 阶段与 `is-tv-exiting` 一样禁用列表指针事件；退场时间线开头显式关掉 showreel。移动端无 hover，保留原有的行/屏重叠面积预览 |
| 关机状态 | 未 hover 时 `.tv-all-vids` 无 `.has-preview`，showreel 透明度 0，屏面只剩磷光灰绿玻璃（`--tv-screen-*` 空闲色板）与原照片的边框反光——即「关机但仍是块玻璃」，不是黑洞也不是节目画面 |
| 照片层级 | hero `.intro-photo-box` 提升到 `z-index: 4`（标题字 2、图条在其下），照片去掉 `mix-blend-mode: difference` 以原色浮在最上层，标题字在四周环绕；照片内层 `top: -100px -> 0` + `object-position: 50% 12%` 消除裁顶与底部黑带。简介肖像同理：photo-box `z-index: 3`、大标题 `z-index: 1`，照片永远在文字之上 |
| 字号与行长 | `.work-items-headline` 改为 `clamp(22px, 2.3vw, 38px)`（移动端 15px，与 mobile-polish 对齐）；作品 teaser 明确设为 13px + `0.06em` 字距的说明文字级；正文栏宽 `min(46vw, 34em)`、第二段 `min(52vw, 38em)`（原 70vw），行长以 em 封顶不随视口无限拉长；拉丁文本 `:not(.zh)` 用 `clamp(20px, 1.8vw, 29px) / 1.5` 行高，使英文简介完整落在 100vh 舞台内，中文保持 `clamp(21px, 2.35vw, 36px)` 的设计字号；联系屏邮箱升到 `clamp(19px, 1.5vw, 24px)`，版权/署名 15/14px |
| 电话亭出场 | 挂载观察提前到 `rootMargin: 120% 0px`（约一屏之前开始下载解码，电视退场期间完成）；入场触发改为 `.contact-inner top 80% -> top 18%`，只在联系屏真正接管画面后开始、落定后不久结束；运动为两拍：`power2.out` 的上升减速（`y: 11svh, scale: .92, fade`）+ 一小段过冲回稳（`-0.7svh -> 0`），模拟重物落位，仍只写 transform、槽位不动；模型自转保留老版速度（`0.18 rad/s` 等价于老版 `0.003/帧`） |
| 顺滑度（参考 danielspatzek.com 的编排习惯） | 该站的顺滑来自三件事：钉住舞台 + 明确的「到达—停留—离开」拍、运动末端减速、以及重资源在入场前就绪。本轮据此把简介文案的到达/推出由线性 `ease: none` 改为 `power1.inOut`（滚动驱动下表现为两端减速，不再像传送带急停），电话亭与电视均改为「入场前预载」。ScrollSmoother `0.65 / 0.9` 与全站 `scrub: true` 的直接对应保持不变——惯性只由一层负责 |

### 新增/更新的回归契约

- `desktop television stays off until a work row is hovered`：到达电视与滚动列表经过时 `data-preview-active=false` 且无 `.tv-cover`；hover 第二行后点亮《鼠疫》画面且粘性保留；进入电话阶段再次熄屏。
- `the hero artwork floats above the headline words that surround it`：照片盒 z-index 高于标题字、照片混合模式为 `normal`、照片中心命中测试落在照片盒内。
- `works headline and second-paragraph measure are set at reading scale`：1440 下作品标题 > 20px、第二段行宽 ≤ 55vw 且 > 320px。
- 电话亭既有契约（槽位恒定、transform 入场、最终落位）在新的 `80% -> 18%` 触发与两拍运动下继续成立：中间采样缩放介于起止之间、最终 `scale 1 / y 0 / opacity 1`。

# 作品集滚动动画：旧版对照与本轮修复

## 对照范围与结论

- **旧版基准**：Git `3b26627`（2023-03-10），检查了页面滚动控制、Locomotive Scroll 配置、简介/作品/联系区样式及电话亭模型。
- **本轮修改前**：Git `24de17a`，实际运行当前 React Router 8、GSAP ScrollTrigger/ScrollSmoother 和 R3F 版本，逐个比较桌面、短屏、平板及手机画面与滚动状态。
- **结论**：旧版值得保留的是“滚动位置直接控制镜头、读完一拍再换场”的编排，不是把旧版固定 `vw` 坐标或 Locomotive/旧框架搬回来。当前桌面 `smooth: 0.65, speed: 0.9` 和直接 `scrub: true` 已接近旧版 `lerp: 0.08, multiplier: 0.9` 的跟随感；本轮重点修复布局、生命周期、屏幕所有权和出场时机。

## 具体差异、问题与方案

| 项目 | 旧版及修改前的差异 | 本轮方案 |
| --- | --- | --- |
| 滚动控制 | 旧版 Locomotive 管惯性、GSAP 直接 scrub；修改前已有 Smoother，但手机先创建基础触发器、再单独创建一套并杀掉部分基础触发器；CSS/JS 以 480px 为手机边界，481–767px 容易落入不适合窄屏的桌面编排。 | 保留桌面 Smoother 与直接 scrub，手机使用原生滚动；合并到一个 `gsap.matchMedia` 生命周期，CSS 和 JS 统一以 767px 为边界，切换宽度时清理旧 pin/状态后重建。 |
| 简介肖像 | 修改前竖幅照片被扩成横向遮罩，虽然将取景移向顶部，巨大左上圆角和裁切仍会遮住照片；短屏时视觉组也可能与顶部导航挤在一起。原图本身有黑色围巾，并非覆盖层。 | 遮罩维持原图 **1080:1438** 比例、`object-fit: contain`，保留轻微圆角及旋转展开；位置同时受视口宽高约束。桌面照片、标题和右侧正文分区，正文到位后停留一拍再共同退出。 |
| 手机简介与第二组图 | 修改前图片、文字在固定高度内同时横移，390×844 的两段简介会压住图片或超出可读区域。 | 第一段只短暂停住肖像，正文置于其后的正常文档流；第二段照片在正文上方单独横移，正文自由换行，不覆盖图片。320px 短屏也可以继续滚动阅读。 |
| 字号与中文 | 旧版简介正文约 `2.5vw` / 手机 `23.5px`；修改前桌面正文是 `clamp(15px, 1.85vw, 28px)`，手机作品标题又被覆盖为 20–29px、署名约 9.5px。部分中文使用康熙部首/兼容字符，在缺少系统中文字库时出现方框。 | 桌面简介正文按宽高共同缩放（不小于 18px），手机正文 21–25px；手机作品标题 26–36px、署名 12px，行高随内容增长。规范化中文字符，增加按 Unicode 范围加载的 Noto Sans TC/SC 回退字体。 |
| 作品与电视 | 旧版强调作品先读完，电视再熄屏/旋转放大；修改前手机在退场 spacer 到达视口 56% 就开始放大，最后作品仍在画面中。作品、号码和退场的回调也可能互相覆盖；桌面短行重叠触发区时，正向和反向停在同一位置可能选中不同作品。 | 手机将退场空间改为 `205svh`，触发改为 `top 10%`：最后作品离开后才放大；按屏幕重叠选手机预览，桌面按固定阅读线选最近作品。电话/退场阶段独占屏幕，基于 trigger **progress** 同步所有权，快速跳跃或反向越过整个区间也能恢复正确预览。 |
| 电视到联系区 | 修改前手机 TV 放大、白场与号码区叠在一起，会出现白—黑—白的突兀色带及多余空场。 | 先进入黑场，手机号码获得一拍阅读时间，再经单次黑到白过渡进入联系区；电视完全退场后才开始手机电话亭入场。桌面仍保留电视玻璃上的号码停留。 |
| 3D 电话亭 | 旧版使用固定位置/vw，模型每帧持续自转；修改前尽管引入 GLB 和错误边界，画布仍可能在宽短屏落到视口外，且“JS 模块已加载”被当成“模型已显示”。桌面的 `IntersectionObserver` 预加载距离还会被 Smoother 的裁切容器限制。 | 画布变为联系区内有界舞台，桌面位于前两行标题侧边，手机位于标题上方；相机 `[0,0,6]`、FOV 45，转为以正面为中心的缓慢有限幅摆动。使用 ScrollTrigger 的同一滚动坐标提前进入预加载区；模型真正挂载后才淡入画布，离开预加载区卸载、返回时重新等待就绪。失败时收起空舞台并重新测量滚动范围，联系方式仍可用。 |
| 底部标题和跑马灯 | 修改前联系区被固定为 `100svh` 并 `overflow: hidden`，标题只按 `vw` 计算；1568×724 中首行会越过视口上缘，画布可能落在屏幕外。跑马灯行高不足时字形上下缘也会被切。 | 联系区最小一屏、内容可自然增长；三行字号同时受宽高约束，给字形和描边留边。跑马灯只在水平方向裁切以形成循环，增加垂直行高；字号随窄屏调整，确保循环各阶段至少有一组完整的“Contact me”。邮箱和电话号码提供可操作的 `mailto:` / `tel:` 链接。 |
| 无障碍动态效果 | 修改前即使用户启用减少动态效果，仍有 pin/scrub、跑马灯及持续渲染的 3D。 | `prefers-reduced-motion: reduce` 下不创建固定滚动镜头，图片和文字回到正常流；跑马灯静止，3D 使用按需静态帧。 |

## 保留的已有改进

- 电视照片和屏幕仍共享同一个 **2560×1707** 场景；玻璃遮罩坐标仍为 `left: 43.3594%`、`top: 57.4107%`、`width: 12.8125%`、`height: 15.7006%`。没有把旧版依赖视口的电视坐标直接搬回来。
- 已有优化脚本生成约 **1.66 MB** 的 `telephone.glb`；成功时不会同时请求约 36.79 MB 的原始 `.gltf`。资源和现有配置化内容、Archive 路由继续保留。
- 移动端画面与短屏布局取舍不同于旧版：优先完整阅读，而不是强行让肖像和长正文同屏重叠。

## 本轮验证与限制

- 已用真实 Chromium/软件 WebGL 检查 320×568、390×844、600×800、768×1024、1440×900、1568×724、2560×1440 的联系区文字与画布几何；390×844 和 1440×900 真实加载 GLB，确认红色电话亭、三行标题和跑马灯可见。
- 连续采样手机作品、电视放大、黑场、号码、白场、电话亭入场，以及从联系区快速反向跳回作品；桌面也检查号码停留、电视退场和反向恢复作品预览。模拟延迟/失败模型请求，检查只在真实 ready 后显示，失败时不留下空画布槽。
- 中英文、屏幕尺寸跨越 767px、减少动态效果，以及电视原图与玻璃遮罩对齐均有自动回归；详见 `tests/scroll-runtime.spec.ts`、`tests/portfolio-layout.spec.ts` 和 `tests/tv-geometry.spec.ts`。
- `npm run typecheck`、`npm run build` 通过；生产构建在临时 Chromium 配置下分别以桌面与 iPhone 触屏模拟运行完整回归，**各 33/33 通过（共 66 项）**。构建仍提示部分 chunk 大于 500 kB；3D 代码仍按需加载。
- 本环境无法从 Playwright 的下载源安装 WebKit，因此**本轮没有声称 Safari/WebKit 或真实手机硬件已验证**。仓库默认 `npm run test:scroll` 仍面向 WebKit；可在有浏览器依赖的 CI 或本机再运行，并建议用实体 iOS/Android 验证触控惯性、字体与低端 GPU 表现。

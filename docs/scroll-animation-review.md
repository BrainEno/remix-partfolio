# 滚动与电视场景动画审查

## 审查基准

- 旧版最佳工作组合：`3b26627`（2023-03-10）。重点参考 Locomotive Scroll `lerp: 0.08`、`multiplier: 0.9`，GSAP `scrub: true`，以及电视先熄屏、再旋转放大退场的节奏。
- 当前审查版本：`9fa4d6a`。保留其 React Router 8、配置化内容、响应式 `matchMedia`、移动端原生滚动和按需加载架构，不恢复已废弃依赖。
- 电视原图在旧版与当前版本中像素一致，尺寸为 **2560 × 1707**，没有透明屏幕孔洞。因此，对齐必须依据原图坐标，而不能继续把旧版视口数值当作屏幕尺寸。

## 对齐细节

电视屏幕遮罩不再包含任何 `vw` 或独立视口偏移。移动端场景尺寸使用：

```css
width: max(100vw, 149.9707svh);
height: auto; /* aspect-ratio: 2560 / 1707 */
```

这与原图宽高比 `2560 / 1707` 一致，等效于居中的 `object-fit: cover`，但现在屏幕和照片共享可测量的同一个盒子。电视整体退场时的 transform origin 也保持在同一个视觉中心，因此修复不会改变缩放的视觉支点。

## 第二轮验收修正

- **简介照片的上部裁切**：遮罩从 `20vw` 扩展到 `40vw` 后，竖幅照片仍使用 `object-position: 50% 50%`，中心裁切会切过头顶，看起来像被上层黑块遮住。现在在同一个直接 Scrub 时间线中把照片从中心取景同步移到 `50% 0%`；保留原有遮罩、旋转、节奏和宽度展开，但始终保留原图顶部与完整头部。
- **电话号码阶段的电视内容回跳**：电视进入退场后虽然先清空项目图，但作品行 Trigger 的刷新/回调，以及静止鼠标下方经过的作品行 hover，都可能再次点亮屏幕。现在退场状态独占预览权，作品行和 Pin 回调必须让行；`is-tv-exiting` 同时禁止作品行指针事件。只有逆向滚出退场区间才恢复最后一项预览。电视照片、玻璃和屏幕仍共享原有变换，不再让项目图在后段放大时重新出现。

## 第三轮：细节编排与对齐复核

上一轮解决的是「有没有动、动得对不对」；这一轮逐个镜头复核「动得到不到位」。下表只列本轮真正改动的地方。

### 对齐细节

- 号码层与玻璃共用同一组归一化坐标（`left 43.3594%`、`top 57.4107%`、`width 12.8125%`、`height 15.7006%`），所以照片换裁切、视口换尺寸都不会让号码从玻璃上跑掉；`border-radius` 与玻璃一致，放大时不会被方角切到。
- 开场专栏的入场终点（52vw）刻意留出 2vw 右外边距，并与肖像遮罩右缘（50vw + 旋转约 40px）保持约 47px 间距：文案既不压脸，也不贴边。
- 「停顿拍」由时间线留白实现（0.64→0.74 没有补间），因此刷新、改变视口高度都不会改变读文案的时间点。
